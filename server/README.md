# 中継サーバー — 立てなくても遊べる、立てると必ず繋がる

このフォルダは**任意**。無くてもゲームは今まで通り動く。
立てて `index.html` に一行書くと、**直結が張れない回線どうしでも2人プレイが繋がる**。

## これが解く問題

いまの2人プレイは端末どうしの直結(WebRTC)。速くて安いが、
両方が厳しい回線(携帯回線の一部・職場や学校のネットワーク)だと直通が張れず、
30〜80秒待たされた末に「直接つながれませんでした」で終わる。

中継を置くと、その組でも繋がる。しかも**直結と同時に試して速い方を使う**ので、
直結できる相手との速さは今までと変わらない。

## 立て方

```bash
node server/index.js          # :8787
PORT=3000 node server/index.js
```

依存パッケージは無い。`npm install` は不要。Node 22 以上。

動いているか:

```bash
curl localhost:8787/health   # -> ok
curl localhost:8787/stats    # -> {"rooms":0,"players":0,...}
```

## 繋ぎ方

`index.html` の該当行を書き換えるだけ。

```html
<meta name="coop-relay" content="wss://relay.example.com">
```

空のままなら中継は一切使わない。**サーバーを立てない選択がそのまま残る。**

> `wss://`(暗号化)であること。`https://` のページから `ws://` へは繋げない。
> 実運用では前段に TLS 終端(Caddy / nginx / Fly.io / Render など)を置く。

## 中身

| ファイル | 役割 |
|---|---|
| `ws.js` | WebSocket そのもの(RFC 6455)。握手・フレーム・ping・close |
| `relay.js` | あいことばの部屋と、そこへの中継。流量制限つき |
| `index.js` | 起動口 |

**ゲームの中身を一切知らない。** 届いたものを部屋の他の人へ流すだけなので、
ゲームのメッセージが増えてもサーバーを直す必要がない。

## 実測(このリポジトリの `test/server.test.js` と同じ環境)

スナップショット1通 = 2,211 バイト(実際のワールド配信と同じ大きさ)。

| | 中継の遅延(中央値) | p95 | 全体の流量 |
|---|---|---|---|
| 2人 | 0.35ms | 0.69ms | 34 KB/秒 |
| 3人 | 0.40ms | 0.57ms | 68 KB/秒 |
| 4人 | 0.36ms | 0.66ms | 106 KB/秒 |
| **50部屋 / 100接続** | **0.44ms** | **1.63ms** | **1,696 KB/秒** |

50部屋を回して CPU 20%・メモリ 96MB(計測用クライアント100個も同じプロセスに居る値なので、
サーバー単体はこれより軽い)。**小さな VPS 1台で数十部屋は持てる。**

ここに出ているのはサーバー内部の処理時間だけで、実際の遅延には回線の往復が加わる。
そちらが支配的になる — つまり**サーバーは律速ではない**。

## 意図的にやっていないこと

- **圧縮(permessage-deflate)** — まず正しく動くことを優先した。人数を増やすときに効く
- **ワールドの計算** — いまもホスト端末が計算している。サーバーは運ぶだけ。
  サーバー側で計算する形にすると「ホストだけ遅延ゼロ」の不公平と
  「ホストが抜けると終わる」が消える。土台(`test/headless.js`)は用意済み
- **認証** — あいことばを知っている人が入れる。5分で消える合言葉なので、
  いまの規模ではこれで釣り合っている

## 守っているもの

| | |
|---|---|
| 1接続あたり | 90通/秒・200KB/秒 を超えたら切る |
| 1部屋 | 4人まで |
| プロセス全体 | 500部屋まで |
| 1メッセージ | 512KB まで |
| 無言の部屋 | 10分で畳む |
| 切れた接続 | 30秒ごとの ping に応えなければ切る |

`/stats` は部屋数と人数だけを返す。**誰が何をしたかは持たない。**
