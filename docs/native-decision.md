## 0. 前提が変わった

**「両方のストアに出す」が決まった。** だから問いはもう
「出す価値があるか」ではなく「**どうやって出すのがいちばん確実か**」。

既存の3本（[native-options.md](./native-options.md) /
[store-readiness.md](./store-readiness.md) / [costs.md](./costs.md)）は
「Web のままが妥当」と結論しているが、それは**出さないなら**の話。
出すと決めた以上、その結論は用済みではなく**前提として効く**——
Web を捨てないまま出す、という形の根拠になる。

## 1. 結論

| | 選ぶもの | なぜ |
|---|---|---|
| 土台 | **Capacitor 6** | Canvas 2D の呼び出しが **734箇所**。React Native には canvas が無く、移植ではなく作り直しになる |
| Android | **Capacitor**（TWA ではなく） | TWA は「ネット越しにサイトを開く殻」で、触覚も課金も足せない。**iOS と同じ殻に揃えるほうが安い** |
| iOS | **Capacitor + ネイティブ実装を3つ** | 包んだだけは 4.2 で落ちる。落ちない状態を作るのが本体の作業 |
| Web | **正典として残す** | 「QRをかざして今すぐ4人」はインストールを挟むと死ぬ。ここが一番いい部分 |

**要点はひとつ。作業の本体は Capacitor で包むことではない。**
包むのは半日で終わる（実際、この判断を書いている時点で**もう終わっている** → §3）。
本体は **Apple のガイドライン 4.2（最低限の機能）を通せる中身を足すこと**で、
それは同時に「ネイティブにした意味」そのものでもある。

## 2. なぜ TWA ではなく Capacitor か（Android）

Android だけなら TWA（$25・審査が緩い）が最短に見える。採らない。

| | TWA | Capacitor |
|---|---|---|
| 中身 | Chrome が URL を開くだけ | アプリの中に資産が入る |
| オフライン | **サーバーが要る**（SW 頼み） | 端末内で完結 |
| 触覚・課金・Play Games | **足せない** | 足せる |
| iOS と共通か | **別物**。iOS 用に作り直し | **同じ殻** |

**2つのストアに出すなら、殻は1つにしたほうが安い。**
TWA を選ぶと Android 用と iOS 用で別の作業が2本立ち、
触覚やストアのランキングを足すときに Android 側をやり直すことになる。

## 3. もう出来ていること

`native/` に殻がある。**このコンテナ（Linux・Mac 無し）で、両プラットフォームの
足場まで実際に通した。**

```
native/
  package.json          Capacitor 6 + haptics / app / status-bar / screen-orientation
  capacitor.config.json appId: app.emojiblasters.game  appName: Emoji Blasters
  copy-web.mjs          ゲーム本体を www/ へ写す（白名簿。docs/ や test/ は入らない）
  android/              npx cap add android 済み
  ios/                  npx cap add ios 済み
```

`npm run sync` で `www/` を作り直して両方へ配る。実際に走らせて、
`android/app/src/main/assets/public/` と `ios/App/App/public/` の両方に
資産が入るところまで確認した。

### copy-web.mjs が要る理由

このゲームには**ビルド工程が無い**ので、Capacitor に素直に webDir を渡すと
`docs/` も `test/` も `tools/` も `server/` も `.git` もアプリに埋まる。
白名簿で `index.html` / `manifest.webmanifest` / `og.png` / `src/` / `icons/` / `fonts/`
だけを写す。**黒名簿にしない**のは、新しく足したフォルダが黙って混入するから。

サービスワーカーの登録は殻の中では外している。中身は端末に埋まっていて
ネットワークから読まないので、SW を残すと「キャッシュのキャッシュ」になり、
更新の筋道が二重になる。

## 4. Apple 4.2 を通すために足すもの

「Web を包んだだけ」と判断されると落ちる。`docs/native-value.md` の台帳で
**8項目中8項目が0件**だった——触覚もプッシュも課金も、一度も取りに行っていなかった。

| | 状態 | 4.2 に効く | 見積り |
|---|---|:--:|---|
| **触覚** | **済**（`src/native.js`） | ○ | 完了 |
| **Game Center / Play Games** | 未 | ○ | 2〜3日 |
| **プッシュ通知** | 未 | ○ | 3〜4日 |
| 画面の向きの固定 | プラグイン導入済・未配線 | — | 1時間 |
| ステータスバー | プラグイン導入済・設定済 | — | 完了 |
| 課金 | 未 | ○ | 出さない判断でよい |

### 触覚は入れた

`src/native.js` が実行時に `window.Capacitor.Plugins.Haptics` を見にいく。
**`import '@capacitor/haptics'` とは書いていない**——1行でも書けば
このリポジトリは npm とビルド工程を持ち、いちばんの性質を失う。

- アプリ … 本物の触覚エンジン（iOS の Taptic Engine / Android の VibrationEffect）
- ブラウザ … `navigator.vibrate`（実質 Android のみ）
- どちらも無い … 黙って何もしない

配線したのは節目だけ: **ベル取得 / コンボ倍率が上がった瞬間 / 被弾 / ボス撃破**。
1体倒すごとに震わせると手が鈍って、強い場面が強く感じられなくなる。
60ms の間引きも入れてある。設定は「画面のゆれ」と同じつまみにぶら下げた
（ゆれが苦手な人は触覚も苦手なことが多く、2つに割ると片方だけ切って
「まだ震える」になりやすい）。

### プッシュがいちばん噛み合う

このゲームには**デイリーチャレンジとストリークという復帰の仕掛けが既にあるのに、
呼び戻す手段だけが無い**。Web では届かない。ネイティブにする理由として、
これが一番はっきりしている。

## 5. 測って消えた「ネイティブにすれば」

出すと決めた今でも、**期待してはいけないこと**は書いておく。

| よく言われる | 実測 | 判定 |
|---|---|---|
| ネイティブなら速くなる | フレーム時間の 88% は JS でなくブラウザのラスタ側。同じ CPU で解像度を半分にすると 30fps → 60fps | **✗** Capacitor は同じ WebView・同じ raster・同じ DPR。直したのは Web 側（`src/env.js` の解像度自動調整） |
| オフラインで遊べるようになる | 回線を切っても既に起動して遊べる（app shell 39件） | **✗** Web で成立済み |
| 起動が速くなる | 12.6秒待たせていたのは third-party のフォント CDN 1本。同梱して **187ms** | **✗** Web 側の問題で、Web 側で直った |
| 保存が消えなくなる | `localStorage` が例外を投げる環境でも起動して遊べる | **△** 落ちはしないが、iOS が PWA のストレージを捨てると進行は失われる。**ここはネイティブが本当に効く** |

## 6. 順番

1. **本番の URL を README に書く。** デプロイは既に動いている（Vercel）。
   ストア提出には**プライバシーポリシーを公開URLとして貼る**必要があり、
   本文は `docs/privacy.md` にあるのに置き場所が無い。
2. **中継サーバーを立てる**（Fly.io 月$2〜7 → [costs.md](./costs.md)）。
   `index.html:12` に1行書けば**4人プレイが公開状態で成立する**。
   いまは空なので、コードは4人ぶんあるのに公開版は2人まで。
   **ストアのスクリーンショットに「最大4人」と書くなら、先にこれ。**
3. **Android から出す**（$25・審査が速い）。`npm run android` → Android Studio。
   最初の判断材料はここで得る。
4. **Game Center / Play Games を足す。** 既存の匿名ランキング
   （`src/leaderboard.js`）の裏を差し替える形で入る。
5. **iOS**（年$99）。`npm run ios` → Xcode。**Mac が要る。**
   4.2 に対しては触覚・Game Center・完全オフライン・プッシュで説明する。

## 7. このコンテナで出来なかったこと

正直に書いておく。ここを曖昧にすると「動いた」と「動いたことになっている」の
区別が消える。

| | |
|---|---|
| **できた** | `cap add android` / `cap add ios` / `cap sync`、設定、資産のコピー、触覚の配線（ブラウザ側の分岐まで） |
| **できていない** | **APK も IPA もビルドしていない。** Android SDK が無く（java と gradle はある）、iOS は macOS が要る |
| **できていない** | **実機で触覚が鳴るのを確かめていない。** コードの分岐はテストで縛ったが、Taptic Engine が震えたのは見ていない |
| **できていない** | ストア審査、Game Center、プッシュ |

§5 の「ネイティブは速くしない」も Chromium での測定であって、
**WKWebView で同じとは証明していない**（同じ結論になる可能性が高い、までしか言えない）。
