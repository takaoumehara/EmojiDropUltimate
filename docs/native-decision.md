# ネイティブ化する価値はあるのか — 測ったうえでの判断

> 2026-09-04。判断の記録。
> 材料は [native-value.md](./native-value.md)（`src/` の実測・自動生成）、
> [probe-report.md](./probe-report.md)（実ブラウザの実測・自動生成）、
> [sim-report.md](./sim-report.md)（自動プレイ576本・自動生成）。
>
> 既存の3本（[native-options.md](./native-options.md) /
> [store-readiness.md](./store-readiness.md) / [costs.md](./costs.md)）は
> **「プロダクトとして得か」**を見て「Web のままが妥当」と結論している。
> ここはそれを否定しない。**別の軸**を足す。

## 0. 今回、目的がはっきりした

ネイティブ化で取りに行くのは **技術・実績としての価値**。
「遊ぶ人にとって得か」ではない。既存3本はこの軸を評価していない。

軸が変われば答えも変わりうるので、測り直した。

## 1. 先に結論

> **「包むだけ」には実績価値が無い。**
> 実績になるのは Apple 4.2 を通すために書く**ネイティブ実装のほう**であって、
> Capacitor で包む作業ではない。包む作業は半日で終わり、半日ぶんの実績にしかならない。

そして測った結果、**ネイティブ化を推す論拠のうち3つは事実として消えた**。

| よく言われる理由 | 実測 | 判定 |
|---|---|---|
| ネイティブなら**速くなる** | フレーム時間の 88% は JS ではなくブラウザのラスタ側。同じ CPU で解像度を半分にすると 30fps → 60fps。**塗るピクセル数で決まっている** | **✗ 消えた。** Capacitor は同じ WebView・同じ Skia・同じ DPR を通る。直せる場所は Web 側で、実際に Web 側で直した |
| ネイティブなら**オフラインで遊べる** | 回線を切って起動 **できる**／遊べる。app shell 37件がキャッシュ済み。最後まで残っていた書体の穴も、同梱して塞いだ | **✗ 消えた。** すでに Web で成立している |
| ネイティブなら**保存が消えない** | `localStorage` が例外を投げる環境でも起動して遊べる（`src/save.js` のメモリ退避が実際に効いている） | **△ 半分残る。** 落ちはしないが、iOS が PWA のストレージを捨てると**進行は失われる**。ここは実機でないと詰められない |
| ネイティブなら**device API が使える** | 8項目中 **8項目が0件**。触覚もプッシュも課金も、一度も取りに行っていない | **○ 残る。ただし条件つき** —— 包むだけでは 0 のまま |
| ネイティブなら**起動が速い** | 起動を 12.6秒待たせていたのは third-party のフォント CDN 1本だった。同梱したら **187ms** | **✗ 消えた。** Web 側の問題で、Web 側で直った |
| ネイティブなら**見つけてもらえる** | Vercel には出ている（PR のプレビューが Ready になった）が、**その URL がリポジトリのどこにも書かれていない**。検索やランキングに載る導線も無い | **○ 残る。ただし前提が欠けている**（下の G0） |

## 2. ゲート

### G0（前提）— 遊べる場所が、どこにも書かれていない

> **2026-09-04 訂正。** 最初この節は「公開URLが存在しない」と書いていたが、
> それは誤りだった。この PR の Vercel プレビューが Ready になったので、
> **デプロイ自体は動いている**。正しくは「**URL がリポジトリのどこにも
> 書かれていない**」——README にも docs にも無く、`tools/native-audit.mjs` の
> 台帳でも「未」のままになる。

実務上これは効く。ストア提出には**プライバシーポリシーを公開URLとして貼る**必要があり
（→ [store-readiness.md](./store-readiness.md)）、その貼り先が決まっていない。
本文は `docs/privacy.md` にあるのに、置き場所が無い。

そして中継サーバーは立っていないので、公開されていても co-op は2人までのまま
（`index.html:12` が空、→ [status.md](./status.md)）。

**遊ばれていないゲームのストア掲載は、実績として弱い。**
「ストアに出した」より「出して、人が遊んだ」のほうが強く、
後者には**書き留められた**公開URLと、家庭の外の遊び手が要る。
ここが埋まる前にネイティブへ行くのは、順番が逆になる。

### G1（意思）— ネイティブ実装を3つ以上書くか

`docs/native-value.md` の表で **0件が8項目**。
このうち Apple 4.2 に効くのは **触覚・プッシュ・課金**の3つ。

- **書くなら** → ネイティブ化には実績価値がある。書くもの自体が実績になる。
  とくに**プッシュ通知**は、このゲームに固有の噛み合わせがある:
  デイリーチャレンジとストリークという**復帰の仕掛けが既にあるのに、
  呼び戻す手段だけが無い**。ここは埋めれば効く穴で、かつ Web では届かない。
- **書かないなら** → **価値はゼロ**。既存3本の結論（Web のまま）がそのまま正しい。
  包んだだけのアプリは 4.2 で落ちやすく、通っても職歴には「WebView を包んだ」としか書けない。

### G2（性能）— ✗ 不合格。ネイティブは何も直さない

実測（`docs/probe-report.md`、CPU を1/4に絞った状態）:

```
DPR 2 … p50 33.4ms（30fps） / 33.3ms超え 78%
DPR 1 … p50 16.7ms（60fps） / 33.3ms超え  0%
```

CPU プロファイルの自己時間は **88% が `(program)`（ブラウザのラスタ側）**、
一番重い JS 関数ですら 2.7%。つまり**塗るピクセル数だけで決まっていた**。

Capacitor は同じ WebView の中で同じ raster を通るので、これは**そのまま持ち込まれる**。
実際の解決は解像度の自動調整で、`src/env.js` に入れた（30fps → 60fps）。
**Web 側で直る問題を、ネイティブ化の理由に使ってはいけない。**

### G3（中核の温存）— 設計しないと不合格

このゲームの一番いいところは「URLを送る → 全員が今すぐ入れる」。
インストールを挟むとそこが消える（→ [costs.md](./costs.md) の同じ指摘）。

**これを殺さない形は一つしかない: Web を正典のまま残し、ネイティブは
「戻ってくる人のための殻」に限定する。**
`?join=CODE` は App Links / Universal Links で、入っていればアプリへ、
入っていなければブラウザで即プレイ。

**この分岐が成立しないならネイティブ化は中核機能に対して純損失。**
検証方法: 招待を受け取ってから遊び始めるまでの手数と秒数を、
Web と ストア経由 で並べて数える。

### G4（費用）

| | 費用 | 審査 | 4.2 リスク |
|---|---|---|---|
| Android（TWA / Capacitor） | **$25 一度きり** | 数時間〜 | **低い**（WebView 方式が通常どおり受理される） |
| iOS | **年$99** | 数日〜 | **高い**（包むだけだと落ちる） |

## 3. 順番

1. **G0 を埋める** —— 本番の URL を README に書く（デプロイは既に動いている）。
   プライバシーポリシーをその URL の下に置く。中継を立てて4人を成立させる。
   ネイティブ化とは無関係に、これをやらないと何も始まらない。
2. **家庭の外の人に遊ばせる。** 判定は「言われなくても2回目を始めるか」だけ。
   `src/diag.js` の `cameBack()` がその器で、もう入っている。
3. G1 に **YES と言えるなら** → Android から。$25、審査が速く、
   触覚・プッシュ・Play Games を実際に書いて、それを実績にする。
4. iOS はそのあと。$99 と 4.2 のリスクを、実際の利用数を見てから引き受けるか決める。

## 4. この判断で「まだ測れていない」こと

正直に書いておく。

- **iOS の実機がない。** 無音スイッチ下の音、PWA のストレージ破棄、
  ホーム画面追加後の挙動は、Chromium のエミュレーションでは分からない。
  G2 の結論（ネイティブは速くしない）は Chromium の測定で、
  WKWebView でも同じとは**証明していない**（同じ結論になる可能性が高い、までしか言えない）。
- **Capacitor で実際に包んでいない。** この Linux コンテナには java と gradle はあるが
  Android SDK が無く、iOS は macOS が要る。包む作業の実費は見積りのままで、実測ではない。
- **面白いかどうか。** 自動プレイ576本でも実ブラウザの測定でも、これは出てこない。
