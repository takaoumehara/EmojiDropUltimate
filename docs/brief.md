# EMOJI DROP ULTIMATE — 設計ブリーフ / 意思決定の記録

> このファイルは「なぜ今この形なのか」を残すためのもの。
> 会話は消えるが、判断の理由が残っていれば別の人(別のAI)が続きを作れる。

## 1. これは何か

方向がステージ毎に変わる絵文字シューティング。Web(Vercel)配信、
**ビルド工程なし・外部ライブラリなし・オフライン動作**が制約であり売り。

## 2. 破ってはいけない原則

| 原則 | 理由 |
|---|---|
| **外部依存を足さない** | 「URL 1本で即遊べる」が最大の強み。CDN/フレームワークを入れた瞬間に、オフライン動作と起動速度という差別化が消える |
| **サーバーはゲーム中の経路に入れない** | シューティングは弾を避けるゲーム。往復遅延は体験を壊す。サーバーは「出会う瞬間」だけに使う |
| **キーが無くても遊べる** | Gemini・KV・TURN が全部無くても、ゲームは完全に成立する。機能は劣化するが壊れない |
| **絵文字の役割を混ぜない** | プレイヤーが選べるキャラの絵文字は、敵やボスに**絶対**使わない。混ざると「自分がどれか」が壊れる |
| **足すより削る** | 機能過多で一度「ごちゃごちゃ」に陥っている。迷ったら削る |

## 3. 主要な設計判断

### 3-1. ふたりでプレイ = WebRTC P2P + ホスト権威
- **P2P直結**(遅延20〜80ms)。シグナリング(`/api/signal`, Upstash)は SDP 交換のみ、5分で消滅。
- **世界の正はホスト**。敵・弾・ベル・ボスはホストだけが計算し、約15Hzでスナップショット配信。
  ゲストは補間して映し、自機と自分の弾だけローカルに動かす(=操作遅延ゼロ)。
- **なぜ**: 各端末で乱数・AI難易度調整・天気を独立に回すと必ずズレる(実際にズレた)。
- **既知の弱点**: ホストが1人のプレイヤー端末なので、ホストが落ちると世界が消える。
  3〜4人や遠隔の安定運用に進むなら、中立の常駐サーバーへ移すのが正攻法(ゲーム側の同期ロジックはそのまま流用可)。
- **残機はチーム共有**。片方だけ取り残される状態を構造的に作らないため。

### 3-2. 章(チャプター)構成
6ステージ=1章。制覇→勝利演出→次章が開く。第1章は手書き、第2章以降はテーマを
章ごとに決定論シャッフルして6つ(重複なし)生成し、章が進むほど強くなる。
- **なぜ**: 6つだけだと短すぎ、無限だと終わりが無くて疲れる。「区切りのある無限」にした。

### 3-3. 集中モード
その場に踏みとどまると連射が上がり、移動が遅くなる。
- **なぜ**: スマホは指1本が移動で塞がるので、撃つボタンは足せない。
  既にできる「止まる」に意味を持たせ、**攻めるか避けるかの判断**を作った。

### 3-4. 天気連動の効き方(混乱しやすいので明記)
- **ルール**(落雷・夜・風・敵速度・スコア倍率)は**全モード**に効く。
- **テーマ生成**に天気を使うのは**エンドレスAIのみ**。

### 3-5. 音
録音を再生せず、Web Audio で合成。テーマ毎の音色パレット + 緊張度で層が増減。
別プロジェクト(typespace)の生成音楽から移植したのは**技法だけ**で、思想は移植していない。
- 採用: コード生成リバーブ、非整数倍音の鐘、互いに素な周期による非反復、
  同一音集合の回転による安全な転調、拍グリッドへの量子化。
- **不採用**: 「不協和を作らない」原則。あちらは瞑想作品なので緊張が不要だが、
  シューティングは緊張と解放が快感の源なので、そのまま持ち込むと平坦になる。
- **先読みスケジューラ**: setTimeout は数ms揺れる。25ms ごとに 200ms 先までを
  AudioContext の絶対時刻で予約する方式に変えた。素人臭さの最大の原因は
  音色ではなくタイミングの揺れなので、ここが一番効いた。
- **ヒステリシス**: 緊張度でレイヤーを出し入れすると、閾値付近でパタパタする。
  上がる閾値と下がる閾値をずらして解決(0.30↑/0.20↓ 等)。
- 度数(スケール上の位置)で作曲しているので、和音がどう回っても調から外れない。
  外れる音は「ピンチ」の1音だけ、意図的に。
